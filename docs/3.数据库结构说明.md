# 数据库结构说明

本文档描述 A股量化分析系统 SQLite 数据库的完整表结构。数据库文件路径：`data/aquant.db`，使用 WAL 模式，共 37 张表。

---

## 〇、自动增量同步流程（auto-sync）

`python main.py data auto-sync` 一键完成全量+增量数据同步，共 14 步，按依赖顺序执行：

### 同步步骤详解

| 步骤 | 表名 | 同步模式 | 同步方法 | 说明 |
|------|------|---------|---------|------|
| 1 | t_trading_date | 全量（每次清空重写） | `sync_trading_dates()` | 从东财 get_trading_dates_by_year 同步 1991 年至今全部交易日，是后续所有步骤的依赖 |
| 2 | t_stock_info | 全量（INSERT OR REPLACE） | `sync_stock_info()` | 同步全部 A 股基本信息，并回填申万行业分类 |
| 3 | t_stock_in_sw | 全量（先清空后插入） | `sync_shenwan_industry_detail()` | 读取 docs/ 目录下含"申万行业"的 xlsx 文件，全量写入申万行业分类明细 |
| 4 | t_etf_info | 全量（INSERT OR REPLACE） | `sync_etf_info()` | 同步全部 ETF 基本信息 |
| 5 | t_index_info | 全量（INSERT OR REPLACE） | `sync_index_info()` | 同步全部指数基本信息，并自动将 11 个核心指数标记为 `is_sync=1`（上证、深证、创业板、沪深300、中证500、中证1000、上证50、红利等） |
| 6 | t_stock_in_index | 增量 | `sync_index_constituents(s_date, e_date)` | 按交易日遍历，同步 `is_sync=1` 的核心指数成分股（含权重、市值、PE/PB） |
| 7 | — | 脚本调用 | `_run_tdx_sector_script()` | 调用通达信板块脚本同步板块成分股（外部脚本，需在通达信目录执行） |
| 8 | t_stock_daily | 增量 | `sync_stock_daily(codes, s_date, e_date)` | 5 线程并发同步所有 A 股日频行情（开高低收量额等） |
| 9 | t_index_daily | 增量 | `sync_index_daily(codes, s_date, e_date)` | 5 线程并发同步指数日频行情 |
| 10 | t_etf_daily | 增量 | `sync_etf_daily(codes, s_date, e_date)` | 5 线程并发同步 ETF 日频行情 |
| 11 | t_finance_prime | 增量 | `sync_financial_data(codes, s_date, e_date)` | 按交易日遍历，调用截面接口同步财务主要指标 |
| 12 | t_finance_deriv | 增量 | `sync_finance_deriv_data(codes, s_date, e_date)` | 按交易日遍历，调用截面接口同步财务衍生指标（分 8 批请求共 142 个字段） |
| 13 | t_stock_mktvalue | 增量 | `sync_stock_mktvalue(codes, s_date, e_date)` | 同步每日市值指标 |
| 14 | t_valuation_data | 增量 | `sync_valuation_data(codes, s_date, e_date)` | 同步每日估值数据（PE/PB/PS/PEG/股息率等） |

### 增量日期计算规则

增量同步的日期范围由 `_calc_incremental_range(table_name, default_start='20210101')` 统一计算：

1. **确定终点日期**：调用 `_get_latest_trade_date()` 获取 ≤ 今天的最近交易日（周末/节假日自动回退到上一个交易日）
2. **确定起点日期**：
   - 调用 `_get_max_sync_date(table_name)` 查询 `t_sync_data_log` 表中该表的 `MAX(data_date)`
   - 若日志中有记录 → 从该日期开始续传（INSERT OR REPLACE 语义允许重复同步最后一天）
   - 若日志中无记录 → 从默认起始日期 `20210101` 开始重新同步（即从未成功完成过同步，或日志丢失）
3. **交易日校验**：查询 `t_trading_date` 确认日期范围内是否有交易日，无交易日则跳过该步

### 核心设计原则

- **日志可信原则**：`t_sync_data_log` 是增量断点续传的**唯一**可信凭证。只有当整张表同步成功后才调用 `_refresh_sync_data_log` 刷新日志（先 DELETE 旧日志，再 INSERT DISTINCT 日期）。中途失败不会写入日志，下次会从断点重新开始。
- **幂等安全**：所有写入均使用 `INSERT OR REPLACE`，重复同步同一日期不会产生重复数据或错误。
- **线程并发**：行情类同步（股票/指数/ETF 日线）使用 5 线程并发，请求间隔 0.1 秒。
- **截面接口**：财务主要指标和财务衍生指标按交易日遍历调用截面接口（非逐股历史查询）。
- **白名单 merge**：API 数据 merge 采用白名单方式，只保留 merge 键列 + 请求的指标列，丢弃非指标列（data_type、rpt_type 等）避免多批 merge 时列冲突。

### 1. t_stock_daily - 股票日频数据

**同步方法：** `DataSync.sync_stock_daily(stock_list, start_date, end_date)`

| trade_date | DATE | NOT NULL | 交易日期 |
| stock_code | VARCHAR(20) | NOT NULL | 股票代码（如 000001.SZ） |
| bob | TIMESTAMP | | 开始时间 |
| eob | TIMESTAMP | | 结束时间 |
| open | REAL | | 开盘价 |
| high | REAL | | 最高价 |
| low | REAL | | 最低价 |
| close | REAL | | 收盘价 |
| volume | REAL | | 成交量 |
| amount | REAL | | 成交额 |
| position | REAL | | 持仓量 |
| frequency | VARCHAR(20) | | 频率 |
| pre_close | REAL | | 前收盘价 |
| vwap | REAL | | 成交量加权平均价 |
| suspend_flag | INTEGER | DEFAULT 0 | 停牌标记（1=停牌） |
| created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**约束：** `UNIQUE(trade_date, stock_code)`

**索引：**

| 索引名 | 字段 | 说明 |
|--------|------|------|
| idx_t_stock_daily_code | stock_code | 按股票代码查询 |
| idx_t_stock_daily_date | trade_date | 按日期查询 |

## 九、系统

### 34. t_sync_data_log - 数据同步完成日志

**同步方法：** 无独立同步方法，由 DataSync 内部自动写入（`_refresh_sync_data_log`）

记录每张增量表各日期的**已成功同步完成**的日期清单。这是增量同步断点续传的唯一可信凭证——只有整张表完整同步成功后才会刷新此表。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 自增主键 |
| table_name | VARCHAR(50) | NOT NULL | 数据表名（如 t_stock_daily） |
| data_date | DATE | NOT NULL | 已同步完成的日期 |
| sync_date | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 同步时间戳 |

**约束：** `UNIQUE(table_name, data_date)` — 同一表同一日期只有一条记录

**索引：**

| 索引名 | 字段 | 说明 |
|--------|------|------|
| idx_sync_data_log_table | table_name | 按表名查询 |
| idx_sync_data_log_date | data_date | 按日期查询 |

**设计原则：**
- 增量同步时，`_get_max_sync_date(table_name)` 仅查询此表的 `MAX(data_date)` 作为断点续传起点
- 不回退查询业务表的 `MAX(date)`，因为中途失败时业务表可能有半截数据，不可信
- 每次增量表同步成功后，调用 `_refresh_sync_data_log(table_name, date_column)`：先删除该表旧日志，再从业务表中 SELECT DISTINCT date_column 全量写入，确保日志完整反映业务表状态
