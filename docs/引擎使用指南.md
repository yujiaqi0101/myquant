# 引擎使用指南

> 适用版本：统一事件驱动内核（`src/core/`）
> 设计文档：[docs/plans/引擎统一重构设计文档.md](plans/引擎统一重构设计文档.md)

## 一、架构概览

### 1.1 核心组件

新版统一引擎采用 vnpy 风格的纯事件驱动内核，由 6 大组件构成：

| 组件 | 模块 | 职责 |
|------|------|------|
| **EventEngine** | `src/core/event_engine.py` | 事件总线，回测同步、实盘异步 |
| **Strategy** | `src/core/strategy.py` | 策略抽象基类，3 个生命周期回调 |
| **Context** | `src/core/context.py` | 策略与引擎交互的唯一接口（8 大职责） |
| **DataFeed** | `src/core/datafeed/` | 数据流，历史/实时两种实现 |
| **Execution** | `src/core/execution/` | 撮合层，模拟/实盘两种实现 |
| **RiskManager** | `src/core/risk/` + `src/risk_checks/` | 风控管线，三层 11 个 Check |

### 1.2 三种引擎模式

| 引擎 | DataFeed | Execution | 持久化 | 调度 |
|------|----------|-----------|--------|------|
| `BacktestEngine` | HistoricalDataFeed | SimulatedExecution(backtest) | 内存 | 同步 |
| `PaperEngine` | LiveDataFeed | SimulatedExecution(paper) | 数据库 | 异步 |
| `LiveEngine` | LiveDataFeed | LiveExecution | 数据库+券商 | 异步 |

**核心设计原则**：策略代码只依赖 `Context` 抽象接口，不感知运行模式，同一份策略代码可在回测/模拟盘/实盘间零修改切换。

### 1.3 数据流

```
DataFeed ──推送──> EventEngine ──分发──> Strategy.on_event()
                                              │
                                              ▼
                                        Context.submit_order()
                                              │
                                              ▼
                                        RiskManager.check_order()
                                              │
                                    通过 ─────┴───── 拒绝
                                      │              │
                                      ▼              ▼
                                Execution       OrderEvent(REJECTED)
                                      │
                                      ▼
                                  Fill 成交
                                      │
                          ┌───────────┴───────────┐
                          ▼                       ▼
                    Portfolio.apply_fill     TradeEvent/OrderEvent
```

## 二、策略生命周期

### 2.1 三个回调函数

所有策略必须继承 `Strategy` 基类并实现 3 个抽象方法：

```python
from src.core.context import Context
from src.core.events import Event, EventType
from src.core.strategy import Strategy, register_strategy

@register_strategy("my_strategy")
class MyStrategy(Strategy):
    name = "my_strategy"

    def on_init(self, context: Context) -> None:
        """初始化：订阅数据、设置定时器、预计算。"""
        context.subscribe(["600000.SH"])
        context.add_timer("rebalance", "month_start")

    def on_event(self, event: Event, context: Context) -> None:
        """统一事件处理：通过 event.type 分发。"""
        if event.type is EventType.BAR:
            # K线事件：决策、下单
            ...
        elif event.type is EventType.TIMER:
            # 定时器事件：调仓
            if context.is_timer_due("rebalance"):
                ...

    def on_stop(self, context: Context) -> None:
        """结束清理：释放资源、输出统计。"""
        ...
```

### 2.2 事件类型

策略在 `on_event` 中通过 `event.type` 分发处理，共 8 种事件：

| EventType | 触发时机 | 事件类 | 关键字段 |
|-----------|---------|--------|----------|
| `INIT` | 引擎启动，仅 1 次 | `InitEvent` | timestamp |
| `BAR` | 每个交易日 | `BarEvent` | symbol/open/high/low/close/volume/extra |
| `TICK` | 实时（高频可选） | `TickEvent` | symbol/price/volume |
| `ORDER` | 订单状态变化 | `OrderEvent` | order_id/symbol/direction/volume/status |
| `TRADE` | 每次成交 | `TradeEvent` | fill_id/symbol/price/volume/pnl |
| `TIMER` | 定时器到期 | `TimerEvent` | name/rule |
| `ACCOUNT` | 账户资金变化 | `AccountEvent` | cash/total/pnl/... |
| `STOP` | 引擎停止，仅 1 次 | `StopEvent` | timestamp |

### 2.3 BarEvent 结构

`BarEvent` 是策略最常处理的事件，主体字段为单 symbol 的 OHLC，`extra` 承载全市场数据：

```python
def on_event(self, event: Event, context: Context) -> None:
    if event.type is EventType.BAR:
        # 主体字段（排序后第一个 symbol 的 OHLC）
        print(f"当前K线: {event.symbol} close={event.close}")

        # extra["symbols_bars"] 承载全市场当日数据
        all_bars = event.extra.get("symbols_bars", {})
        for sym, bar in all_bars.items():
            print(f"  {sym}: close={bar['close']}")

        # extra["trade_date"] 承载交易日字符串
        trade_date = event.extra.get("trade_date")  # "2024-01-15"
```

## 三、Context 接口

策略通过 `Context` 与引擎交互，共 8 大职责：

### 3.1 数据访问

```python
# 订阅标的（on_init 中调用）
context.subscribe(["600000.SH", "000001.SZ"])

# 查询历史K线（避免未来函数，不含当日）
closes = context.history("600000.SH", fields="close", count=20)  # List[float]
df = context.history("600000.SH", fields=["open", "close"], count=20)  # DataFrame

# 批量查询多标的历史
result = context.history_multi(["600000.SH", "000001.SZ"], fields="close", count=10)
```

### 3.2 订单操作

支持两种下单方式：

```python
# 方式1：按数量下单
order_id = context.submit_order(
    symbol="600000.SH",
    direction="buy",      # "buy" / "sell"
    volume=100,
    price_type="market",  # "market" / "limit" / "next_open"
)

# 方式2：按目标权重下单（推荐，自动折算股数）
order_id = context.submit_order(
    symbol="600000.SH",
    direction="target",
    target_weight=0.30,        # 目标仓位占总资产 30%
    price_type="target_percent",
)

# 撤单
context.cancel_order(order_id)
```

**价格类型说明**：

| price_type | 行为 |
|------------|------|
| `market` | 按当前市价即时成交 |
| `limit` | 限价单，需指定 `price` 参数，触及即成交 |
| `next_open` | 次日开盘价成交（Pending 订单跨日撮合） |
| `target_percent` | 目标权重，自动折算为目标股数后转为 buy/sell |

**目标权重折算公式**：

```
目标股数 = floor(总资产 × target_weight / 当前价 / lot_size) × lot_size
delta = 目标股数 - 当前持仓量
  delta > 0 → 买入 delta 股
  delta < 0 → 卖出 |delta| 股
  delta = 0 → 不操作
```

其中 `lot_size`：688 开头（科创板）200 股/手，其他 100 股/手。

### 3.3 持仓与账户查询

```python
# 查询单标的持仓（无持仓返回 None）
pos = context.get_position("600000.SH")
# pos = {"quantity": 100, "available": 100, "avg_price": 10.5,
#        "market_price": 11.0, "market_value": 1100.0, "pnl": 50.0, ...}

# 查询全部持仓
positions = context.get_positions()  # {symbol: pos_dict, ...}

# 查询账户资金
account = context.get_account()
# account = {"cash": 500000, "frozen": 0, "market_value": 500000,
#            "total": 1000000, "pnl": 0, "pnl_pct": 0.0,
#            "daily_pnl": 0, "daily_pnl_pct": 0.0}
```

### 3.4 定时器

```python
# 注册定时器（on_init 中调用）
context.add_timer("rebalance", "month_start")

# 判断定时器是否在当前事件中触发（on_event 中调用）
def on_event(self, event, context):
    if event.type is EventType.TIMER:
        if context.is_timer_due("rebalance"):
            # 执行调仓逻辑
            ...
```

**支持的 rule**：

| rule | 触发时机 |
|------|---------|
| `month_start` | 每月第一个交易日 |
| `month_end` | 每月最后一个交易日 |
| `week_start` | 每周第一个交易日 |
| `daily_open` | 每日开盘 |
| `daily_close` | 每日收盘 |

### 3.5 时间与其他

```python

# 写日志
```

## 四、策略开发指南

### 4.1 策略注册

使用 `@register_strategy(name)` 装饰器注册策略，`name` 必须唯一：

```python
from src.core.strategy import Strategy, register_strategy

@register_strategy("my_strategy")
class MyStrategy(Strategy):
    name = "my_strategy"  # 必须与装饰器参数一致
    ...
```

策略文件放在 `src/strategies/<策略目录>/` 下，引擎启动时通过 `auto_discover()` 自动扫描注册。

### 4.2 参数传递

策略参数通过 `params` 字典传入，由 CLI `--param KEY=VALUE` 或直接构造：

```python
# CLI 方式
# python main.py backtest --strategy my_strategy --param top_n=5 --param rebalance_at=month_start

# 代码方式
strategy = MyStrategy(params={"top_n": 5, "rebalance_at": "month_start"})

# 策略内部读取
class MyStrategy(Strategy):
    def __init__(self, params=None):
        super().__init__(params)
        self.top_n = int(self.params.get("top_n", 5))
        self.rebalance_at = str(self.params.get("rebalance_at", "month_start"))
```

### 4.3 完整示例：小市值策略

参考 `src/strategies/3a7b2c01/small_cap.py`，核心逻辑：

```python
@register_strategy("small_cap")
class SmallCapStrategy(Strategy):
    name = "small_cap"

    def __init__(self, params=None):
        super().__init__(params)
        self.top_n = int(self.params.get("top_n", 5))
        self.rebalance_at = str(self.params.get("rebalance_at", "month_start"))
        self._db = None
        self._bought = False

    def on_init(self, context: Context) -> None:
        self._db = context.get_db()
        context.add_timer("rebalance", self.rebalance_at)

    def on_event(self, event: Event, context: Context) -> None:
        # 仅在调仓日的 TIMER 事件触发时调仓
        if event.type is EventType.TIMER and context.is_timer_due("rebalance"):
            self._rebalance(context)

    def _rebalance(self, context: Context) -> None:
        # 1. 查询全市场市值，选最小的 top_n 只
        # 2. 等权配置，每只 target_weight = 1/top_n
        # 3. 对目标股票用 target_percent 下单
        # 4. 对不在目标中的持仓清仓
        ...

    def on_stop(self, context: Context) -> None:
        pass
```

### 4.4 常见模式

#### 模式1：调仓日判断

```python
def on_event(self, event, context):
    if event.type is EventType.TIMER and context.is_timer_due("rebalance"):
        self._rebalance(context)
```

#### 模式2：等权调仓

```python
def _rebalance(self, context):
    target_symbols = self._select_stocks()  # 选股
    weight = 1.0 / len(target_symbols)

    # 买入目标股票
    for sym in target_symbols:
        context.submit_order(sym, direction="target",
                            target_weight=weight,
                            price_type="target_percent")

    # 清仓不在目标的持仓
    for sym in context.get_positions():
        if sym not in target_symbols:
            context.submit_order(sym, direction="target",
                                target_weight=0.0,
                                price_type="target_percent")
```

#### 模式3：T+1 规则

引擎自动处理 T+1：
- 买入当日：持仓 `quantity` 增加，但 `available` 不变（冻结）
- 次日开盘：`settle_new_day()` 解冻，`available` 更新
- 卖出时：自动校验 `available`，不足则拒绝

策略无需关心 T+1 细节，正常调用 `submit_order` 即可。

## 六、风控管线

### 6.1 三层架构

| 层级 | Check | 说明 |
|------|-------|------|
| **法定风控**（必执行） | LimitUpCheck | 涨停过滤（主板10%/创业板科创板20%） |
| | LimitDownCheck | 跌停过滤 |
| | STFilterCheck | ST/*ST/退市股过滤 |
| | NewStockCheck | 新股过滤（上市<60天） |
| | SuspendCheck | 停牌过滤 |
| | TPlusOneCheck | T+1 规则（当日买入不可卖） |
| **订单级** | MaxOrderQtyCheck | 单笔最大下单量（默认100万股） |
| | LotSizeCheck | lot_size 整数倍（688=200/其他=100） |
| **组合级**（可选） | MaxPositionPctCheck | 单持仓仓位上限（默认30%） |
| | MaxPositionsCheck | 持仓数量上限（默认10只） |
| | DailyStopLossCheck | 日亏急停（默认-5%） |

### 6.2 使用风控

```python
from src.risk_checks.factory import build_ashare_risk_manager

# 默认 11 个 Check
rm = build_ashare_risk_manager()

# 自定义参数
rm = build_ashare_risk_manager(
    max_position_pct=0.25,      # 单持仓上限 25%
    max_positions=5,            # 最多持 5 只
    daily_stop_loss=-0.03,      # 日亏 3% 急停
)

# 禁用组合级 Check（仅保留法定 + 订单级，共 8 个）
rm = build_ashare_risk_manager(enable_portfolio_checks=False)

# 完全禁用风控（不推荐）
engine = BacktestEngine(strategy=strategy, db=db, ..., risk_manager=None)
```

### 6.3 风控短路逻辑

任一 Check 不通过即拒绝订单，不再执行后续 Check：

```
LimitUpCheck → LimitDownCheck → STFilterCheck → ... → DailyStopLossCheck
      │
      └─ 不通过 → 返回 RiskCheckResult(passed=False, reason="...")
                                          ↓
                                  订单被拒绝，不进入 Execution
```

## 七、回测结果

### 7.1 BacktestResult 字段

回测返回 `BacktestResult` 对象，包含 22+ 项绩效指标：

| 类别 | 字段 |
|------|------|
| **收益类** | total_return / annual_return / final_equity |
| **交易统计** | trade_count / win_count / loss_count / win_rate / max_win / avg_win / max_loss / avg_loss / profit_loss_ratio |
| **日胜率/涨跌** | daily_win_rate / trading_days / up_days / down_days / max_consecutive_up / max_consecutive_down |
| **回撤类** | max_drawdown / max_drawdown_duration / max_drawdown_period / longest_no_new_high / max_daily_drawdown |
| **日波动** | max_daily_up / max_daily_down |
| **换手率** | annual_turnover |
| **风险调整** | sharpe / calmar |
| **超额收益** | excess_return / excess_annual_return / beta / alpha / information_ratio |

## 十、常见问题

### Q1: 策略如何获取全市场当日数据？

通过 `BarEvent.extra["symbols_bars"]`：

```python
def on_event(self, event, context):
    if event.type is EventType.BAR:
        all_bars = event.extra.get("symbols_bars", {})
        # all_bars = {"600000.SH": {"open":..., "close":..., ...}, ...}
```

### Q2: 如何避免未来函数？

`context.history()` 严格返回当前时间点之前的数据，不含当日。如需当日数据，从 `BarEvent` 中读取。

### Q3: target_weight 和 volume 下单有何区别？

- `volume` 下单：直接指定买卖股数，需自行计算目标仓位
- `target_weight` 下单：引擎自动折算目标股数，自动处理 lot_size 取整，推荐使用

### Q4: 风控被拒订单如何感知？

订单被风控拒绝后，引擎会推送 `OrderEvent(status=REJECTED, reason=...)`。策略可在 `on_event` 中监听：

```python
def on_event(self, event, context):
    if event.type is EventType.ORDER and event.status == "rejected":
        context.log("warning", f"订单被拒: {event.symbol} 原因: {event.reason}")
```

### Q5: 模拟盘如何跨日恢复？

`PaperEngine` 启动时调用 `load_state(account_id)` 从 `account_*` 表读取上日账户状态（现金/持仓/订单），无需手动恢复。

### Q6: 如何禁用部分风控 Check？

```python
from src.core.risk.manager import RiskManager
from src.risk_checks.factory import build_ashare_risk_manager
from src.risk_checks.lot_filter import LimitUpCheck

rm = build_ashare_risk_manager(enable_portfolio_checks=False)
# 或手动构造只含部分 Check 的 RiskManager
rm = RiskManager()
rm.add_check(LimitUpCheck())
# rm.add_check(...) 按需添加
```
