 ## 问题背景
 
 在东财掘金中，`context` 对象在进程重启后会全部丢失。该策略依赖大量 `context` 变量跨日保持状态：
 
 | 变量 | 用途 | 丢失后果 |
 |------|------|----------|
 | `_pending_buy` | 两阶段调仓的待买入目标（卖出后次日记入） | **买入阶段永远不执行** |
 | `_rebalance_month` | 上次调仓月份，防重复触发 | **每月多次调仓** |
 | `_pending_retry_buys/sells` | 涨停/跌停未成交订单重试队列 | **重试失败** |
 | `_entry_info` | 持仓股票的买入日期和价格 | **异动止盈触发逻辑失效** |
 | `_surge_peaks` | 异动后最高价（用于移动止盈） | **无法判断何时触发止盈** |
 | `_surge_mode` | 当前异动监控的股票集合 | **异动监控完全失效** |
 | `_surge_sold_history` | 已异动止盈卖出的记录（防回购） | **可能重复买入急涨股** |
 | `risk_mode` | 正常/减仓/清仓 | **风控状态重置** |
 
 ## 核心思路
 
 1. **单阶段调仓**：将"T日卖出→T+1日买入"改为"同一天卖出+买入"
 2. **利用官方 `get_previous_n_trading_dates` API**：识别每月第一个交易日（无需 `_rebalance_month`）
 3. **异动止盈无状态化**：每次调用时从最近N天价格数据重算峰值和回撤
 4. **重试逻辑简化**：月初非首日时重新选股+重新执行调仓（幂等设计）
 
 ## 具体改造方案
 
 ### 改造1: init() 精简
 
 移除所有状态变量初始化，保留参数设置和 `schedule()`：
 - 移除 `rebalance_count`, `risk_mode`, `target_weights`
 - 移除 `_rebalance_month`, `_pending_buy` 
 - 移除 `_pending_retry_buys/sells`, `_max_retry_days`
 - 移除 `_entry_info`, `_surge_peaks`, `_surge_mode`
 
 ### 改造2: `daily_check()` 重构
 
 用 `get_previous_n_trading_dates(exchange='SHSE', date=today_str, n=1)` 替换 `_rebalance_month`：
 - `上一个交易日月份 != 本月月份` → 本月第一个交易日 → 完整调仓
 - 月初非首日 → 仅重试未成交
 - 每日执行异动止盈
 
 ### 改造3: `_check_surge_stop()` 无状态化
 
 从价格数据中直接计算峰值和回撤，不再依赖 `_entry_info`/`_surge_peaks`/`_surge_mode`：
 - 获取近30个交易日的收盘价序列
 - 计算5日涨幅 + 20日加速比 → 判断是否异动
 - 找到异动后近N天的最高价作为峰值
 - 峰值回落超过阈值 → 卖出
 - 返回 `surge_sold` 集合给调用方
 
 ### 改造4: `_buy_phase()` 参数调整
 
 增加 `surge_sold` 参数替代 `_surge_sold_history`：
 - `surge_sold` 是本次 `_check_surge_stop()` 返回的当日已止盈标的
 - 过滤掉当日已止盈的标的
 
 ### 改造5: `_sell_phase()` 简化
 
 移除对 `_surge_mode` 的检查，改为：不在目标列表中且非涨停/跌停的持仓直接卖出
 
 ### 改造6: 重试逻辑简化
 
 移除 `_pending_retry_buys/sells` 队列，改为月初重新执行调仓时自动重试
 
 ### 改造7: `on_order_status()` 简化
 
 移除所有重试逻辑，仅保留日志打印和止盈统计
 
 ### 改造8: 移除自定义 `get_previous_n_trading_dates`
 
 该函数不再需要，改用官方 gm API 版替代
