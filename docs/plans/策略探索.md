# 股票量化交易策略探索功能 - 实现方案

## 摘要

本方案设计一套股票量化交易策略探索系统，核心流程为：**用户输入策略想法 + 市场数据 + 条件约束 → 系统自动多轮迭代优化 → 输出经过严格验证的最优策略**。系统采用"VectorBT快速探索 + Backtrader精细验证"双引擎架构，以贝叶斯优化（Optuna）为核心优化方法，配合 Walk-Forward 分析、PBO过拟合检测、蒙特卡洛稳健性测试三重验证机制，确保策略的稳健性和可解释性。

---

## 当前状态分析

本项目处于方案设计阶段，尚无现有代码基础。需要从零搭建完整的策略探索系统，包括：
- 策略模板化系统（将自然语言策略想法转化为可执行代码）
- 双引擎回测框架（VectorBT + 系统高质量回测引擎）
- 贝叶斯优化引擎（Optuna）
- Walk-Forward 验证框架
- 过拟合检测与稳健性测试模块
- 结果评估与可视化报告系统

---


### 一、核心模块设计

#### 模块1：策略模板系统

策略模板系统负责将用户的策略想法转化为可执行的回测代码。

#### 模块2：双引擎回测系统

**VectorBT（快速探索阶段）：**
- 用于大规模参数扫描和初步筛选
- 向量化计算，速度极快（千万级数据秒级处理）
- 适合探索阶段快速定位参数大致范围

**高质量回测引擎（精细验证阶段）：**
- 用于通过初步筛选的策略的精细验证
- 事件驱动架构，订单模拟更真实
- 支持更复杂的订单类型和滑点模型

**切换逻辑：**
- 第一轮优化使用 VectorBT 快速扫描参数空间
- 对 Top-N 候选策略使用 高质量回测引擎 进行精细回测
- 最终验证必须使用 高质量回测引擎

#### 模块2：贝叶斯优化引擎（Optuna）

**核心功能：**
- 基于高斯过程建模目标函数（夏普比率）
- 通过 Expected Improvement 采集函数平衡探索与利用
- 支持多目标优化（同时优化收益、风险、稳健性）
- 内置早停机制（基于中间结果剪枝，节省计算资源）

**优化目标：**
- 主目标：夏普比率最大化
- 约束目标：最大回撤 < 阈值、胜率 > 阈值、PBO < 0.3

#### 模块3：Walk-Forward 分析框架

**设计要点：**
- 将数据分为训练窗口和测试窗口
- 在训练集上优化参数，在测试集上验证
- 滑动窗口重复该过程，模拟真实交易中的策略更新
- 默认配置：训练6个月 / 测试1个月 / 步进1个月

**输出指标：**
- 各窗口的样本内（IS）和样本外（OOS）夏普比率
- 性能衰减比率（PDR）= (IS Sharpe - OOS Sharpe) / IS Sharpe
- 各窗口参数稳定性分析

#### 模块4：过拟合检测与稳健性测试

**过拟合检测指标：**

| 指标 | 公式 | 阈值 | 说明 |
|------|------|------|------|
| PDR | (IS Sharpe - OOS Sharpe) / IS Sharpe | < 0.5 | 性能衰减比率 |
| PSI | 最佳夏普 / 参数网格平均夏普 | < 3.0 | 参数稳定性指数 |
| DFR | 观测数量 / 参数数量 | > 20 | 自由度比率 |
| PBO | CSCV框架计算 | < 0.3 | 回测过拟合概率 |

**蒙特卡洛稳健性测试：**
- 交易顺序随机化（10000次模拟）
- 参数抖动测试（参数扰动10%后夏普比率下降<30%）
- 滑点压力测试（2倍滑点下仍保持盈利）
- 通过标准：95%模拟路径下不爆仓，50%分位数仍盈利

#### 模块5：多轮迭代优化与收敛判断

**迭代流程：**
```
开始优化
    │
    ▼
执行贝叶斯优化 → 获得候选参数
    │
    ▼
Walk-Forward验证 → 获取OOS表现
    │
    ▼
过拟合检测 → PBO、PDR、PSI计算
    │
    ▼
蒙特卡洛测试 → 稳健性验证
    │
    ▼
收敛判断？
    │是 → 输出最优策略
    │否 → 调整搜索空间 → 下一轮优化
```

**收敛判断条件（需同时满足）：**
1. 夏普比率稳定：连续3轮OOS夏普变化 < 5%
2. PBO < 0.3（过拟合风险低）
3. 蒙特卡洛存活率 > 95%
4. 参数稳定性：PSI < 3.0
5. 连续2轮无显著改善（早停）

**未收敛时的调整策略：**
- PBO过高 → 缩小参数搜索范围或增加数据量
- PSI过高 → 扩大搜索范围寻找性能高原
- 蒙特卡洛不通过 → 简化策略或减少参数
- OOS夏普过低 → 策略核心逻辑有问题，提示用户重新设计

#### 模块6：策略评估报告系统

**报告内容：**
- 策略描述与参数配置
- 回测绩效指标（夏普比率、最大回撤、年化收益、卡玛比率等）
- Walk-Forward分析结果（各窗口表现、PDR）
- 过拟合检测报告（PBO、PSI、DFR）
- 蒙特卡洛测试结果（存活率、分位数表现）
- 参数敏感性分析（热力图、3D曲面图）
- 交易明细与权益曲线
- 风险提示与建议



## 假设与决策

### 关键决策

1. **双引擎策略**：采用 VectorBT + 高质量回测引擎 而非单一引擎
   - 理由：VectorBT速度快适合探索，高质量回测引擎精度高适合验证，两者互补

2. **贝叶斯优化为主**：以 Optuna 为核心优化方法
   - 理由：样本效率高，适合评估代价高的回测场景，支持多目标和早停

3. **Walk-Forward为必需**：所有策略必须通过WFA验证
   - 理由：这是防止过拟合的最有效手段之一

4. **三层过拟合防线**：WFA + PBO + 蒙特卡洛
   - 理由：单一指标可能失效，多重验证提高可靠性

5. **策略模板化**：用户通过选择模板+配置参数来定义策略
   - 理由：降低使用门槛，确保策略结构规范，便于优化

### 假设条件

1. 用户具备基础量化交易知识，能理解夏普比率、最大回撤等指标
2. 市场数据质量可靠，已处理前复权、停牌等问题
3. 计算资源充足，能支持大规模参数优化
4. 策略想法可转化为明确的规则（不支持完全黑盒的ML策略）

5. 验证报告系统生成的报告包含所有必要信息

### 性能验证
1. VectorBT回测速度：单策略单股票日级数据应在1秒内完成
2. Optuna优化效率：200次trial应在5分钟内完成
3. 系统能同时处理多个优化任务

## 可行性结论

该功能在技术上**完全可行**，且已有成熟的开源生态支持（VectorBT、高质量回测引擎、Optuna等）。核心挑战在于：

1. **过拟合控制**：必须通过严格的统计验证确保策略稳健性
2. **策略模板设计**：需要在灵活性和规范性之间取得平衡
3. **计算资源**：大规模参数优化需要足够的计算能力
