## 三、关键设计决策

### 3.1 Order 类型对接
- 复用 `src.engine.types.Order`（direction 为 `Direction.LONG/SHORT` 枚举）
- 数据库 `direction` 字段存 `'long'/'short'` 字符串，与枚举互转
- 买入开仓 = `Direction.LONG`；卖出平仓 = `Direction.SHORT`（与 backtest_engine 一致）

### 3.2 策略对接
- 复用 `BaseStrategy` 接口（`on_init` / `on_bar` / `exit_checker`），策略无需修改
- 出场检查：调用 `strategy.exit_checker(context, position)`，返回 `ExitCheckResult`
  - 有 `suggested_order` 用之，否则自动生成反向平仓订单（与 backtest_engine 一致）

### 3.3 撮合模式
- `close`：当日收盘价立即成交
- `next_open`：订单标记 `pending`，次日运行时用当日 open 撮合
  - 买单：冻结资金（cash→frozen_cash），次日解冻并实际扣减
  - 卖单：次日才扣减持仓

### 3.4 费用计算（贴近真实 A 股）
- 佣金：万三（0.0003），最低 5 元（买卖双向）
- 印花税：卖出千一（0.001）
- 过户费：沪市双向 0.00001（简化处理，全部股票都收）

### 3.5 市场过滤（参考 backtest_engine 实现）
- ST 过滤：基于 `t_stock_info.stock_name` 含 "ST"/"退"
- 新股过滤：上市未满 60 天（基于 `list_date` + 交易日历）
- 涨跌停过滤：`close >= pre_close * 1.095` 涨停拒买，`close <= pre_close * 0.905` 跌停拒卖
  - 简化处理：统一 10% 阈值（与 backtest_engine 一致）
- 停牌过滤：`suspend_flag != 0`

### 3.6 CLI 风格
- 项目不使用 Rich，统一 `print()` + f-string 表格输出
- 子命令注册参考 `quantlab_cli.py` 的嵌套子命令模式

### 3.7 数据库设计（严格遵循详细设计方案第 3 节）
5 张表：`paper_accounts` / `paper_positions` / `paper_orders` / `paper_trades` / `paper_snapshots`
- 主键与索引按设计方案
- `direction` 字段统一存 `'long'/'short'`

## 四、验证方法

### 自动化测试
```bash
python -X utf8 -m pytest tests/test_paper_trading.py -v
```
覆盖：
- 手续费计算（最低 5 元、万三、印花税、过户费）
- 买入撮合（资金扣减、持仓建立）
- 卖出撮合（持仓移除、盈亏计算）
- Pending 订单次日撮合（资金冻结/解冻）
- 编排器驱动策略生成订单

### 手动验证
1. `python main.py paper --status` — 显示初始 1,000,000 账户
2. `python main.py paper --run --date 2024-01-02` — 模拟首日交易
3. `python main.py paper --run --date 2024-01-03` — 次日撮合 Pending
4. `python main.py paper --status` — 查看资产变动
5. `python main.py paper --positions <策略ID>` — 查看持仓明细

## 五、风险与约束
- 数据库中的市场数据必须是干净的，模拟数据绝不写入（项目规则 1）
- 策略层负责信号，引擎层只负责执行（严格分离）
- 简洁至上，最小实现（不过度设计）
