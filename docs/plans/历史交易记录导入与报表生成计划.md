# 历史交易记录导入与报表生成功能实现计划

## 一、需求概述

开发历史交易记录导入与报表生成功能，支持通过 CLI 指定本地券商导出的 CSV 文件路径，
解析并映射到系统现有报表数据模型，进行完整性/有效性/业务规则验证，最终复用现有
HTMLReporter 报表引擎生成可视化报表。

### 核心需求

1. **CLI 指定 CSV 路径**：无需上传界面，命令行直接指定本地券商导出文件路径
2. **CSV 解析模块**：识别并处理主流券商（华泰、中信、国金、东方财富、同花顺等）格式
3. **数据映射**：将券商字段准确映射到统一 `TradeRecord` 模型，并落库到 `t_broker_trade`
4. **数据验证**：格式验证、数据范围验证、业务规则验证，提供清晰错误提示
5. **复用现有报表引擎**：`src/report/html_reporter.py` 的 HTMLReporter
6. **功能/兼容性测试**：覆盖主流券商格式与不同文件大小

### 2.2 数据库表 `t_broker_trade`

新增表存储导入的历史交易记录：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| trade_date | DATE | 交易日期 |
| trade_time | VARCHAR(20) | 成交时间（可选） |
| stock_code | VARCHAR(20) | 证券代码（归一化为 000001.SZ 格式） |
| stock_name | VARCHAR(100) | 证券名称 |
| trade_type | VARCHAR(10) | 交易类型 buy/sell |
| price | REAL | 成交价格 |
| quantity | REAL | 成交数量（股） |
| amount | REAL | 成交金额 |
| commission | REAL | 手续费/佣金 |
| stamp_tax | REAL | 印花税 |
| transfer_fee | REAL | 过户费 |
| other_fee | REAL | 其他费用 |
| total_fee | REAL | 总费用 |
| net_amount | REAL | 净金额（卖出为正，买入为负） |
| broker | VARCHAR(50) | 券商标识（huatai/citic/gj/eastmoney/...） |
| account | VARCHAR(50) | 资金账号（可选） |
| source_file | VARCHAR(255) | 源 CSV 文件名 |
| imported_at | TIMESTAMP | 导入时间 |

约束：`UNIQUE(trade_date, stock_code, price, quantity, trade_type)`

### 2.3 统一数据模型 `TradeRecord`

```python
@dataclass
class TradeRecord:
    trade_date: str          # YYYY-MM-DD
    stock_code: str          # 归一化代码 000001.SZ
    stock_name: str
    trade_type: str          # 'buy' / 'sell'
    price: float
    quantity: float
    amount: float
    commission: float = 0
    stamp_tax: float = 0
    transfer_fee: float = 0
    other_fee: float = 0
    trade_time: str = ''
    broker: str = ''
    account: str = ''
```

### 2.4 券商格式适配（字段别名映射）

通过"字段别名表"支持多券商格式，按列名自动识别：

| 统一字段 | 华泰 | 中信 | 国金 | 东方财富 | 同花顺 |
|---------|------|------|------|---------|--------|
| trade_date | 成交日期 | 交易日期 | 委托日期 | 交易日 | 发生日期 |
| stock_code | 证券代码 | 证券代码 | 证券代码 | 证券代码 | 证券代码 |
| stock_name | 证券名称 | 证券名称 | 证券名称 | 证券名称 | 证券简称 |
| trade_type | 操作 | 买卖方向 | 操作方向 | 交易类型 | 业务名称 |
| price | 成交均价 | 成交价格 | 成交价格 | 成交均价 | 成交价格 |
| quantity | 成交数量 | 成交数量 | 成交数量 | 成交数量 | 成交数量 |
| amount | 成交金额 | 成交金额 | 成交金额 | 成交金额 | 成交金额 |
| commission | 手续费 | 手续费 | 手续费 | 手续费 | 手续费 |

**识别策略**：读取 CSV 表头，匹配别名表中的列名，匹配度最高者即为该券商格式。

### 2.5 数据验证机制

1. **格式验证**：
   - 日期格式可解析（支持 YYYY-MM-DD / YYYYMMDD / YYYY/MM/DD）
   - 股票代码可归一化（6 位数字 → 添加交易所后缀）
   - 交易类型可映射（买入/卖出/卖/买 → buy/sell）

2. **范围验证**：
   - price > 0
   - quantity > 0 且为 100 的整数倍（A 股规则，可放宽）
   - amount ≈ price × quantity（±1% 容差）

3. **业务规则验证**：
   - 成交金额 = 价格 × 数量（一致性校验）
   - 卖出数量不超过持仓（需累计计算，可选）
   - 日期不晚于今天
   - 手续费非负

### 2.6 报表生成（复用 HTMLReporter）

`TradeReporter` 将导入的交易记录转换为 HTMLReporter 所需的 JSON 结构：
- `performance.json`：汇总指标（总交易数、总金额、总费用、买卖统计）
- `trades.json`：交易记录列表
- `snapshots.json`：按日资金快照

调用 `HTMLReporter.generate()` 生成 HTML，完全复用现有报表引擎的样式与交互。

### 2.7 CLI 命令

新增 `trades` 一级命令：

```bash
# 导入 CSV（自动识别券商格式）
python main.py trades import --file D:\trades\huatai.csv

# 指定券商格式（可选，跳过自动识别）
python main.py trades import --file D:\trades\xxx.csv --broker huatai

# 生成报表（基于已导入数据）
python main.py trades report --broker huatai --start-date 2024-01-01 --end-date 2024-12-31

# 查看导入记录列表
python main.py trades list

# 验证已导入记录
python main.py trades validate

# 交互式菜单
python main.py trades
```
