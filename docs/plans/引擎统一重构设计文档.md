## 一、重构背景与目标

### 1.1 现状问题

当前系统存在 **3套并行引擎**，复杂性过高：

| 引擎 | 位置 | 职责 | 问题 |
|------|------|------|------|
| myquant BacktestEngine | `src/engine/` | v1策略回测 | 已标记废弃，6个v1策略仍在用 |
| QuantLab 多引擎家族 | `src/quantlab/` | v2策略回测（含5个子引擎） | BarEngine/EventEngine等价，SubprocessVBT孤儿 |
| PaperTradingEngine | `src/paper_trading/` | 模拟交易持久化 | 绑定myquant types，v2策略无法接入 |

**核心痛点**：
1. 3套引擎无统一接口，维护成本高
2. v2策略A股风控未串联（功能缺口）
3. v2策略无法做模拟交易（PaperTrading只支持v1）
4. 中间品功能堆积（EventEngine/SubprocessVBT等）

### 1.2 重构目标

1. **统一引擎架构**：基于事件驱动模型，支持 `on_init`/`on_event`/`on_stop` 生命周期回调
2. **策略零修改切换**：同一份策略代码可运行回测/模拟盘/实盘，仅通过依赖注入切换
3. **功能精简**：删除3套旧引擎和11个策略，只保留小市值策略
4. **实盘兼容**：架构原生支持实盘部署，非事后补丁
5. **接口标准化**：统一事件处理接口和数据交互格式
6. **A股风控内置**：法定风控（涨跌停/ST/新股/停牌/T+1）作为管线自动执行

### 1.3 核心决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 重构激进度 | 最激进：完全推翻重写 | 用户明确要求，只保留小市值策略 |
| 回测实盘关系 | 双引擎共享内核 | 策略代码零修改切换回测/实盘 |
| 生命周期设计 | 统一 on_event | 事件驱动，通过 event.type 分发 |
| 订单提交方式 | 主动式 context.submit_order() | vnpy风格，最接近实盘 |
| 运行模式 | 回测/模拟盘/实盘三模式 | 模拟盘=实时行情+模拟撮合+DB持久化 |

## 三、核心抽象接口

### 3.1 EventType 事件类型

8种事件类型，覆盖引擎流转的所有场景：

| 事件类型 | 说明 | 推送时机 |
|----------|------|----------|
| `INIT` | 初始化事件 | 回测开始/实盘启动 |
| `BAR` | K线事件（日/分钟级） | DataFeed按交易日推送 |
| `TICK` | Tick事件（高频可选） | DataFeed实时推送 |
| `ORDER` | 订单状态变化 | 订单提交/成交/撤销/拒绝 |
| `TRADE` | 成交回报 | 每次撮合成交 |
| `TIMER` | 定时器事件 | 调仓日/开盘前/收盘后 |
| `ACCOUNT` | 账户资金变化 | 成交扣款/出入金 |
| `STOP` | 结束事件 | 回测结束/实盘停止 |

### 3.2 Strategy 抽象基类

```python
class Strategy(ABC):
    """策略抽象基类
    
    生命周期：
        on_init(context)              → 初始化（订阅数据、设置定时器、预计算）
        on_event(event, context) × N  → 处理事件（BAR/TICK/ORDER/TRADE/TIMER/ACCOUNT）
        on_stop(context)              → 结束清理
    
    核心原则：
        1. 策略只通过 context 与引擎交互，不直接访问引擎内部
        2. 策略不感知运行模式（回测/模拟盘/实盘），context 由引擎注入
        3. 策略不直接访问数据库，数据通过 context.history() 获取
        4. 策略通过 context.submit_order() 主动下单，不返回订单列表
    """
    
    @abstractmethod
    def on_init(self, context: Context) -> None:
        """初始化回调（必须实现）"""
        pass
    
    @abstractmethod
    def on_event(self, event: Event, context: Context) -> None:
        """统一事件处理（必须实现）"""
        pass
    
    @abstractmethod
    def on_stop(self, context: Context) -> None:
        """结束回调（必须实现）"""
        pass
```

### 3.3 Context 策略上下文

Context 是策略与引擎交互的唯一接口，7大职责：

| 职责 | 方法 | 说明 |
|------|------|------|
| 数据访问 | `subscribe()` / `history()` / `history_multi()` | 订阅数据、查询历史K线 |
| 订单操作 | `submit_order()` / `cancel_order()` | 主动下单、撤单 |
| 持仓查询 | `get_position()` / `get_positions()` | 单symbol/全部持仓 |
| 账户查询 | `get_account()` | 现金/冻结/市值/总资产 |
| 定时器 | `add_timer()` / `is_timer_due()` | 注册定时器、判断触发 |
| 时间查询 | `get_clock()` | 当前回测/实盘时间 |
| 日志 | `log()` / `get_config()` | 写日志、读配置 |

**订单提交接口**：
```python
def submit_order(
    self,
    symbol: str,
    direction: str,           # "buy" / "sell" / "target"
    volume: Optional[float] = None,        # 按数量下单
    target_weight: Optional[float] = None, # 目标持仓权重0-1
    price_type: str = "market",            # "market"/"limit"/"next_open"/"target_percent"
    price: Optional[float] = None,
    order_id: Optional[str] = None,
) -> str:
```

### 3.4 EventEngine 事件总线

支持3种模式：

| 模式 | mode | 数据源 | 撮合 | 持久化 | 调度 |
|------|------|--------|------|--------|------|
| 回测 | `backtest` | HistoricalDataFeed | SimulatedExecution | 内存 | 同步单线程 |
| 模拟盘 | `paper` | LiveDataFeed | SimulatedExecution | 数据库 | 异步多线程 |
| 实盘 | `live` | LiveDataFeed | LiveExecution | 数据库+券商 | 异步多线程 |

## 四、DataFeed 与 Execution 抽象

### 4.1 DataFeed 数据流

| 实现 | 用途 | 数据来源 |
|------|------|----------|
| `HistoricalDataFeed` | 回测 | SQLite按时间顺序读取历史K线 |
| `LiveDataFeed` | 模拟盘/实盘 | 实时行情源（东财掘金API） |

**HistoricalDataFeed 核心方法**：
- `start()`: 从DB加载数据到内存
- `next_bar() -> BarEvent`: 按交易日逐根推送
- `history(symbol, fields, count)`: 切片历史数据（避免未来函数）

**LiveDataFeed 特点**：
- 多线程异步，行情线程生产事件，主线程消费
- 内存缓存最近N根K线供 `history()` 查询
- 模拟盘可降级为"定时从DB读取最新bar"

### 4.2 Execution 执行层

| 实现 | 用途 | 撮合方式 |
|------|------|----------|
| `SimulatedExecution` | 回测/模拟盘 | 内存撮合 + DB持久化 |
| `LiveExecution` | 实盘 | 调用券商API真实下单 |

**三种价格类型 + 目标权重**：
- `market`: 当前市价即时成交
- `limit`: 限价单（触及限价成交）
- `next_open`: 次日开盘价（登记Pending，T+1模拟）
- `target_percent`: 按目标权重调仓（与direction="target"配合）

**目标权重计算逻辑**：
```
目标股数 = floor(总资产 × target_weight / 当前价格 / lot_size) × lot_size
实际下单 = 目标股数 - 当前持仓（正数买，负数卖，0不动）

lot_size 规则：
    - 688开头（科创板）：200股/手
    - 其他：100股/手
```

**A股费用计算**（Execution基类）：
- 佣金：双向，费率0.025%，最低5元
- 印花税：仅卖出，费率0.05%
- 过户费：双向，费率0.002%

## 五、RiskManager 风控管线

### 5.1 风控三层架构

```
策略调用 context.submit_order()
    ↓
RiskManager 风控管线
    ├── 1. PreTradeCheck（交易前检查）
    │   - 涨跌停过滤（LimitUpCheck/LimitDownCheck）
    │   - ST股票过滤（STFilterCheck）
    │   - 新股过滤（NewStockCheck，上市<60天）
    │   - 停牌过滤（SuspendCheck）
    │   - T+1规则检查（TPlusOneCheck）
    ├── 2. PortfolioCheck（组合级检查，可选）
    │   - 单持仓仓位上限（MaxPositionPctCheck，默认30%）
    │   - 持仓数量上限（MaxPositionsCheck，默认10只）
    │   - 日亏急停（DailyStopLossCheck，默认-5%）
    └── 3. OrderSizeCheck（订单检查）
        - 单笔最大量（MaxOrderQtyCheck，默认100万股）
        - lot_size整数倍（LotSizeCheck，科创板200/其他100）
    ↓ 通过
Execution.submit()
    ↓ 拒绝
推送 OrderEvent(status="rejected")
```

### 5.2 A股风控工厂函数

```python
def build_ashare_risk_manager(
    enable_portfolio_check: bool = True,
    max_position_pct: float = 0.30,        # 单持仓上限30%
    max_positions: int = 10,                # 最多持10只
    max_order_qty: int = 1_000_000,         # 单笔最大100万股
    daily_stop_loss: float = -0.05,         # 日亏5%急停
) -> RiskManager:
```

**Check执行顺序**：A股法定风控（必须执行）→ 订单级检查 → 组合级检查（可选）。任一Check不通过即拒绝订单。

### 5.3 风控上下文数据

风控Check通过 `context_provider` 获取最新上下文：
- `current_time`: 当前时间
- `current_price`: 当前价格
- `bar`: 当日bar数据
- `stock_info`: 股票基本信息（ST/上市日期/停牌状态，预加载）
- `position`: 当前持仓
- `account`: 账户信息
- `portfolio`: 全部持仓

## 六、数据结构与持久化

### 6.1 核心数据结构

支持期货期权多空方向扩展（当前A股仅多头，架构支持空头）：

```python
class Direction(str, Enum):
    BUY = "buy"        # 买入
    SELL = "sell"      # 卖出
    TARGET = "target"  # 目标权重

class PositionDirection(str, Enum):
    LONG = "long"      # 多头（A股股票默认）
    SHORT = "short"    # 空头（期货/期权卖出开仓）

class OpenClose(str, Enum):
    OPEN_LONG = "open_long"      # 多开
    CLOSE_LONG = "close_long"    # 多平
    OPEN_SHORT = "open_short"    # 空开（期货/期权）
    CLOSE_SHORT = "close_short"  # 空平（期货/期权）
```

**Position T+1处理**：
- `today_bought`: 今日买入量（不可卖）
- `settle_new_day()`: 次日开盘时调用，`today_bought` 转入 `available`

**Portfolio开仓/平仓配对**：
- 买入时记录待平仓Position
- 卖出时与开仓配对生成Trade（含盈亏计算）

### 6.2 BacktestResult 绩效指标

完整绩效指标（含沪深300基准对比）：

| 类别 | 指标 |
|------|------|
| 收益类 | 总收益、年化收益、最终资产 |

| 日波动 | 单日最大上涨、单日最大下跌 |
| 换手率 | 年换手率 |
| 风险调整 | 夏普比率、卡尔玛比率 |
| 超额收益 | 超额收益（累计）、超额年化收益、Beta、Alpha（年化）、信息比率 |

## 七、小市值策略与CLI集成

### 7.1 小市值策略重写

基于新 `Strategy` 基类重写，保留原有逻辑：

**策略逻辑**：
1. 月度调仓：每月第一个交易日调仓
2. 选股逻辑：从全市场选取市值最小的N只股票
3. 等权配置：每只股票分配 1/N 仓位
4. 排除条件：ST/新股/停牌/涨跌停（由风控管线自动过滤）

**参数**：
- `top_n`: 持仓数量（默认5）
- `rebalance_at`: 调仓频率（month_start/month_end/week_start）
- `min_market_cap` / `max_market_cap`: 市值过滤
- `universe`: 股票池（None=全市场）

### 7.2 三种引擎实现

| 引擎 | DataFeed | Execution | 持久化 | 调度 |
|------|----------|-----------|--------|------|
| `BacktestEngine` | HistoricalDataFeed | SimulatedExecution(backtest) | 内存 | 同步 |
| `PaperEngine` | LiveDataFeed | SimulatedExecution(paper) | 数据库 | 异步 |
| `LiveEngine` | LiveDataFeed | LiveExecution | 数据库+券商 | 异步 |

**回测引擎生命周期**：
1. 启动DataFeed（加载历史数据）
2. 策略on_init（订阅数据、设置定时器）
3. 事件循环：逐日推送BarEvent → 策略决策 → 风控检查 → 撮合成交
4. 结束：计算绩效指标，返回BacktestResult

**模拟盘引擎特点**：
- 加载历史账户状态（恢复运行）
- 每日收盘后持久化（账户/持仓/订单/快照）
- 支持跨日Pending订单（T+1）

**实盘引擎特点**：
- 从券商同步真实持仓（reconcile）
- 订单状态由券商异步回报
- 持仓以券商为准

### 7.3 CLI 命令设计

```bash
# 回测（历史数据验证）
python main.py backtest \
    --strategy small_cap \
    --start-date 2024-01-01 \
    --end-date 2024-06-30 \
    --initial-cash 1000000 \
    --benchmark 000300.SH \
    --top-n 5 \
    --rebalance-at month_start

# 模拟盘（实时行情+模拟撮合）
python main.py paper --strategy small_cap --initial-cash 1000000

# 实盘（真实下单）
python main.py live --strategy small_cap --token YOUR_EASTMONEY_TOKEN

# 策略管理
python main.py strategy --list
python main.py strategy --show small_cap
```

## 附录：关键设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 引擎架构 | vnpy风格事件驱动 | 实盘兼容性最强，工业标准 |
| 策略接口 | 统一on_event | 事件驱动，通过event.type分发 |
| 订单提交 | 主动式context.submit_order() | 最接近实盘，支持拆单/撤单 |
| 运行模式 | 回测/模拟盘/实盘三模式 | 模拟盘是实盘前最后一道验证 |
| 目标权重 | target_percent价格类型 | 引擎自动计算delta，策略代码简洁 |
| lot_size | 科创板200股/其他100股 | A股交易规则 |
| 多空方向 | 预留PositionDirection/OpenClose | 未来支持期货期权 |
| 基准对比 | 沪深300默认，可配置 | 标准超额收益计算 |
| 策略版本 | 彻底删除 | 用户要求，现阶段过于复杂 |
| 风控集成 | 引擎内置RiskManager管线 | A股法定约束不可跳过 |
