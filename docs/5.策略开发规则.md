## 1. 总体原则

### 1.1 双轨架构

myquant 同时存在两套策略体系：

| 维度 | v1（已废弃） | v2（推荐） |
|------|--------------|------------|
| 基类 | `src.engine.base_strategy.BaseStrategy` | `src.quantlab.signals.base.SignalStrategy` |
| 接口 | `on_init(ctx)` + `on_bar(ctx) -> List[Order]` | `signal(ctx) -> pd.DataFrame` |
| 引擎 | `src.engine.backtest_engine.BacktestEngine`（已废弃） | `src.quantlab.engine.BarEngine` 等 |
| 职责 | 选股 + 调仓 + 风控耦合在策略内 | 策略只产信号，组合/执行/风控分层解耦 |
| 适用 | 仅 6 个存量 v1 策略兼容运行 | **所有新策略必须采用** |

### 1.2 核心理念

v2 范式把"想要什么"和"如何成交"彻底解耦：

```
策略层 (SignalStrategy)        只输出 signal ∈ {-1, 0, 1}
    ↓
组合层 (PortfolioConstructor)  signal → 目标权重
    ↓
执行层 (Execution)             目标权重 → 订单
    ↓
撮合层 (BarEngine)             扣现金、记成交、推 TradeBook
```

**一套策略可以无修改地跑在 BarEngine / EventEngine / VectorBT / TickEngine 上。**

### 1.3 禁止事项

- 禁止新增 v1 策略（继承 `BaseStrategy`）
- 禁止在 `signal()` 中执行副作用（写文件、起线程、改全局状态、`print` 调试）
- 禁止在策略层直接调用 `DatabaseManager` 或东财 API（数据由 `DataAdapter` 注入到 `ctx.data`）
- 禁止在策略层手写仓位计算、佣金扣减、撮合逻辑（交给组合层和引擎）
- 禁止把不可序列化对象（数据库连接、模型、文件句柄）作为策略属性

## 2. 目录结构与命名

### 2.1 标准目录结构

每个策略位于独立 ID 目录下：

```
src/strategies/
├── __init__.py                     # 自动发现入口
├── _strategy_map.json              # 策略名 → ID 映射
└── <策略ID>/                        # 8 位十六进制 ID，如 3a7b2c01
    ├── __init__.py                 # Python 包标记（空文件即可）
    ├── <策略名>_v<版本号>.py        # 策略实现文件
    └── 策略路径.md                  # 策略说明与版本历史
```

### 2.2 命名规则

| 项目 | 规则 | 示例 |
|------|------|------|
| 策略 ID | 8 位十六进制小写 | `3a7b2c01` |
| 策略名 | snake_case，业务语义 | `small_cap`、`pb_roe_monthly` |
| 策略文件名 | `<策略名>_v<版本号>.py` | `small_cap_v1.py`、`small_cap_v2.py` |
| 策略类名 | PascalCase，与文件名对应 | `SmallCapV2`、`PbRoeMonthlyV2` |
| 策略 `name` 属性 | `<策略名>_v<版本号>` | `small_cap_v2` |

### 2.3 ID 生成

新策略 ID 用以下命令生成（确保全局唯一）：

```python
import uuid
print(uuid.uuid4().hex[:8])
```

### 2.4 必备文件

每个策略目录必须包含 3 个文件：

1. `__init__.py` — 空文件即可
2. `<策略名>_v<版本号>.py` — 策略实现
3. `策略路径.md` — 策略说明与版本历史（模板见 [§13](#13-策略路径md-模板)）

## 3. 策略基类契约（SignalStrategy）

### 3.1 继承与接口

```python
from src.quantlab.signals.base import SignalStrategy
import pandas as pd


class MyStrategy(SignalStrategy):
    """策略类必须遵循以下约定"""

    # 推荐：明确类名（用于注册表与 CLI）
    name = "my_strategy_v1"
    description = "我的策略 - 一句话描述"

    def __init__(self, top_n: int = 30, min_amount: float = 500.0):
        # 1) 所有参数存为基本类型（int/float/bool/str）→ 可 JSON 序列化
        self.top_n = int(top_n)
        self.min_amount = float(min_amount)

        # 2) 启动即失败：参数合理性校验
        if self.top_n < 1:
            raise ValueError(f"top_n must be >= 1, got {top_n}")

    def signal(self, ctx) -> pd.DataFrame:
        # 3) 输出：完整 DataFrame(index=date, columns=symbol, values∈{-1,0,1})
        out = {}
        for sym in ctx.data:
            out[sym] = self._signal_one(ctx, sym)
        return pd.DataFrame(out).astype("int8")

    def _signal_one(self, ctx, sym: str) -> pd.Series:
        """单标的信号逻辑（私有方法）"""
        df = ctx.data[sym]
        # 单标的逻辑
        return (df["close"] > df["close"].rolling(20).mean()).astype("int8")
```

### 3.2 signal 取值约定

| 值 | 含义 |
|----|------|
| `1` | 做多（目标持仓） |
| `0` | 空仓（不持有） |
| `-1` | 做空（暂未强制使用，留位） |

### 3.3 signal 输出格式

- **必须是 `pd.DataFrame`**
- `index` = bar 时间（DatetimeIndex，单调递增）
- `columns` = symbol（多标的）
- `value` ∈ `{-1, 0, 1}`，整型（推荐 `int8` 节省内存）
- 每根 bar 取 `signal.iloc[i-1].to_dict()` → scores，由适配器翻译成订单

### 3.4 参数规范

- 所有 `__init__` 参数必须为基本类型：`int` / `float` / `bool` / `str`
- 参数必须可 JSON 序列化（用于 `ExperimentTracker` 入库）
- 在 `__init__` 中做参数合理性校验，**启动即失败**，不要在 `signal()` 跑一半才崩
- 参数命名清晰，避免单字母（`n` / `k` 等除外）

### 3.5 signal() 内部禁止事项

- ❌ `print()` / `logging` 调试输出
- ❌ 起线程 / 进程
- ❌ 修改全局变量
- ❌ 读写文件
- ❌ 调用数据库 / 网络 API
- ❌ 持有不可序列化对象

### 3.6 自动注册

策略类继承 `SignalStrategy` 即视为可注册。两种注册路径：

1. **显式装饰器**（推荐）：
   ```python
   from src.quantlab_adapters import register_signal_strategy

   @register_signal_strategy
   class MyStrategy(SignalStrategy):
       name = "my_strategy_v1"
       ...
   ```

2. **自动发现**：`discover_v2_strategies("src.strategies")` 扫描所有 `*_v2.py` 文件，自动注册其中的 `SignalStrategy` 子类。

### 3.7 工厂方法（推荐）

为方便 `ExperimentRecord` / CLI 用 kwargs 构造，推荐提供显式工厂：

```python
def make_my_strategy(
    top_n: int = 30,
    min_amount: float = 500.0,
) -> MyStrategy:
    """显式工厂：避免某些调用方依赖默认参数顺序。"""
    return MyStrategy(top_n=top_n, min_amount=min_amount)
```

### 3.8 参数网格（推荐）

为支持 `Optimizer` / `ParallelOptimizer` 网格搜索，推荐在策略文件末尾定义参数网格常量：

```python
MY_STRATEGY_PARAM_SPACE: dict = {
    "top_n":      [10, 20, 30, 50],
    "min_amount": [200.0, 500.0, 1000.0],
}
```

## 4. 数据流与上下文

### 4.1 数据加载入口

策略**不直接访问数据库**。数据由 `DataAdapter` 加载并注入到 `ctx.data`：

```python
from src.quantlab_adapters import from_quantlab_db

data = from_quantlab_db(
    db_path="data/aquant.db",
    start_date="2024-01-01",
    end_date="2024-12-31",
    stock_codes=None,  # None = 全市场
)
# data: Dict[symbol, DataFrame]
```

### 4.2 ctx.data 结构

`ctx.data` 是 `Dict[symbol, pd.DataFrame]`，每个 DataFrame：

- `index`：`pd.DatetimeIndex`（单调递增）
- 必含列：`open` / `close` / `pre_close`
- 透传列：`high` / `low` / `volume` / `amount` / `vwap` / `suspend_flag`
- 合并列（由 `from_quantlab_db` 自动合并）：
  - `list_date` / `stock_name`（来自 `t_stock_info`，供 RiskCheck 使用）
  - `pb` / `market_cap`（来自 `t_valuation_data`，按 `stock_code` 分组 `ffill` / `bfill`）
  - `roe` / `revenue_growth`（来自 `t_finance_prime`，取最近报告期）

### 4.3 ctx.cache

`ctx.cache` 是因子缓存。策略调用 `quantlab.factors` 内的因子函数时自动走缓存：

```python
from src.quantlab.factors.ma import ma
from src.quantlab.factors.rsi import rsi
from src.quantlab.factors.atr import atr
from src.quantlab.factors.boll import boll

# 自动缓存，key 包含 symbol，互不干扰
fast_ma = ma(ctx, symbol, 20)
slow_ma = ma(ctx, symbol, 60)
```

**禁止在策略中手写 `rolling` 重复计算已有因子。**

### 4.4 ctx.symbols

`ctx.symbols` 返回所有可交易标的列表（`list(ctx.data.keys())`）。

### 4.5 数据缺失降级

策略应对数据缺失做优雅降级，不要直接抛异常：

```python
def _signal_one(self, ctx, sym: str) -> pd.Series:
    df = ctx.data[sym]

    # 缺列降级为 True（不参与过滤）
    if "roe" in df.columns and df["roe"].notna().any():
        roe_ok = (df["roe"] > self.roe_threshold).fillna(False)
    else:
        roe_ok = pd.Series(True, index=df.index)

    return roe_ok.astype("int8")
```

## 5. 组合构建层

策略只输出"想买什么"，仓位大小由 `PortfolioConstructor` 决定。

### 5.1 内置构造器

| 构造器 | 规则 | 适用场景 |
|--------|------|----------|
| `EqualWeight` | `score > 0` 的 symbol 等权分配 `1/N` | 等权选股 |
| `TopN(n=N)` | 按 score 降序取前 N，等权 `1/N` | 动量轮动、多因子选股 |

### 5.2 调用方式

```python
from src.quantlab.portfolio_construction import TopN, EqualWeight

constructor = TopN(n=30)
# 或
constructor = EqualWeight()
```

### 5.3 自定义构造器

继承 `PortfolioConstructor` 实现 `construct(scores, timestamp) -> TargetPortfolio`：

```python
from src.quantlab.portfolio_construction.base import PortfolioConstructor
from src.quantlab.portfolio_construction.target_portfolio import TargetPortfolio

class MyConstructor(PortfolioConstructor):
    def construct(self, scores: dict, timestamp) -> TargetPortfolio:
        # scores: Dict[symbol, float]
        # 自定义权重逻辑
        weights = self._compute_weights(scores)
        return TargetPortfolio(timestamp=timestamp, weights=weights)
```

### 5.4 CLI 中的 TopN 自动推断

CLI（`quantlab run` / `backtest`）会从策略参数自动推断 `TopN(n=?)`：

- 优先取 `top_n` 参数
- 其次取 `n_positions` / `top_pct` / `max_positions`
- 默认 30

## 6. 执行与撮合层

### 6.1 执行模型

`TargetWeightExecution` 把 `TargetPortfolio` 转成 `Order` 列表：

- `lot_size`：手数（A 股 100 股一手）
- `position_tolerance`：调仓容忍度（默认 2%，小于此比例不调仓）
- 价格为 NaN（停牌/未上市）→ 跳过

### 6.2 佣金与滑点

```python
from src.quantlab.execution import PercentageCommission, PercentageSlippage

commission = PercentageCommission(rate=0.0003)   # 万三
slippage = PercentageSlippage(rate=0.0002)       # 万二
```

A 股默认工厂（推荐）：

```python
from src.quantlab_extras import build_ashare_execution

execution = build_ashare_execution(
    commission_rate=0.00025,  # 万 2.5
    slippage_rate=0.0001,     # 万 1
    lot_size=100,
    position_tolerance=0.02,
)
```

### 6.3 BarEngine 撮合流程

每根 bar 的完整流水线：

1. `scores = strategy.signal(ctx).iloc[i-1]` — 取前一根 bar 的分数
2. `target = portfolio_constructor.construct(scores, timestamp)` — 目标权重
3. `orders = execution.generate_orders(portfolio, target, prices)` — 调仓单
4. 执行 Order：应用滑点、扣佣金、更新 Portfolio、生成 Fill、推 TradeBook
5. 收盘后 `portfolio.record(timestamp, bar_close)` — 记录权益

### 6.4 现金不足保护

BarEngine 内置现金不足降仓：买入时若 `cost > portfolio.cash`，自动按能买得起的最大量降仓。

## 7. 风控层（A 股专用）

### 7.1 默认 RiskManager

A 股默认风控由 `build_ashare_risk_manager()` 构造，包含 8 个 check：

| Check | 作用 |
|-------|------|
| `LimitUpCheck` | 涨停不买 |
| `LimitDownCheck` | 跌停不卖 |
| `STFilterCheck` | ST / *ST / 退市股过滤 |
| `TPlusOneCheck` | T+1 规则（当日买入次日才能卖） |
| `NewStockCheck` | 新股过滤（默认上市 < 60 天） |
| `SuspendCheck` | 停牌过滤 |
| `OrderSizeCheck` | 单笔最大下单量 |
| `KillSwitch` | 日亏急停（默认 5%） |

### 7.2 调用方式

```python
from src.quantlab_extras import build_ashare_risk_manager

rm = build_ashare_risk_manager(
    new_stock_days=60,
    max_daily_loss_pct=0.05,
)
```

### 7.3 禁用风控

仅在研究对比场景禁用：

```bash
python main.py quantlab run -s small_cap_v2 --no-risk-check
python main.py quantlab run -s small_cap_v2 --no-execution-cost
```

### 7.4 策略层不再实现风控

v1 策略在 `exit_checker()` 中实现止损/止盈/ATR 动态止盈。**v2 策略不再如此**：

- 止损 / 止盈 / 动态止盈 → 委托给 `RiskManager`
- 净值回撤降仓 → 委托给 `RiskManager` 的 `KillSwitch`
- 市场趋势过滤 → 在 `signal()` 中表达（如 `close > MA(60)` 才输出 1）

## 8. 版本管理

### 8.1 数据库表

策略版本信息存储在 `strategy_versions` 表：

| 字段 | 说明 |
|------|------|
| `strategy_id` | 策略目录 ID（固定，同策略所有版本共享） |
| `strategy_name` | 策略名称 |
| `version` | 版本号（`v1` / `v2` / ...） |
| `file_path` | 策略文件相对路径 |
| `is_active` | 1 = 运行时加载此版本 |
| `description` | 变更说明 |

### 8.2 运行时加载逻辑

`StrategyRegistry.auto_discover()` 扫描所有 ID 子目录，**仅加载 `is_active=1` 的版本**。

`SignalStrategyRegistry.discover_v2_strategies()` 扫描所有 `*_v2.py` 文件并自动注册。

### 8.3 创建新版本

当策略逻辑调整时，必须新建版本，**不得直接修改旧版本文件**：

```python
from src.data.database import DatabaseManager
from config.config import DATABASE_CONFIG

db = DatabaseManager(DATABASE_CONFIG['path'])

# 1. 复制 & 修改策略文件
# cp small_cap_v1.py small_cap_v2.py
# 编辑 small_cap_v2.py

# 2. 注册新版本（自动激活，旧版本设为未激活）
db.create_new_strategy_version(
    'small_cap', 'v2',
    'src/strategies/3a7b2c01/small_cap_v2.py',
    '变更说明：增加 ROE 因子过滤'
)

# 3. 切换版本
db.set_active_version('small_cap', 'v1')  # 回退
db.set_active_version('small_cap', 'v2')  # 启用新版本

# 4. 更新 策略路径.md 版本历史
```

### 8.4 版本号规则

- 主版本号（`v1` → `v2`）：策略范式变更（如 v1 BaseStrategy → v2 SignalStrategy）
- 次版本号（`v2` → `v3`）：策略逻辑重大调整（参数变化、选股条件变化、调仓频率变化）
- 小修改（参数微调）：可在同版本内修改，但需更新 `策略路径.md` 变更说明

## 9. 研究流水线（6 Stage SOP）

新策略开发完成后，必须跑完整 6 stage SOP 验证。入口在 `src/quantlab/examples/run_pipeline.py`。

### 9.1 6 个 Stage

| Stage | 名称 | 目标 | 通过标准 |
|-------|------|------|----------|
| 1 | 单次回测 | 拿到基线 | 跑通无异常 |
| 2 | 双引擎一致性 | VBT 快引擎 vs BarEngine 精确引擎 | `consistency_score >= 0.8` |
| 3 | 网格搜索 | 从参数空间挑 Sharpe top_k | top_k 结果合理 |
| 4 | Walk-Forward | 滚动窗口 OOS 评估 | `avg_test_sharpe >= 0.5`、`avg_test_max_dd <= 0.3`、`stability_score >= 0.6`、`parameter_drift <= 0.3` |
| 5 | 入库 | 元数据 + 指标写 SQLite | 入库成功 |
| 6 | 反向信号 sanity check | 信号取反，收益应变差 | 反向收益显著低于正向 |

### 9.2 调用方式

**薄壳写法**（每个策略一个文件，推荐）：

```python
# src/quantlab/examples/run_my_strategy.py
from run_pipeline import run_sop
from quantlab.signals import MyStrategy, MY_STRATEGY_PARAM_SPACE

if __name__ == "__main__":
    run_sop(
        strategy_cls=MyStrategy,
        param_space=MY_STRATEGY_PARAM_SPACE,
        base_params={
            "top_n": 30,
            "min_amount": 500.0,
        },
        tag="my_strategy_baseline",
        note="首次基线测试",
    )
```

### 9.3 跳过 Stage

数据不足或环境限制时可跳过部分 stage：

```python
run_sop(
    strategy_cls=MyStrategy,
    param_space=MY_STRATEGY_PARAM_SPACE,
    base_params={...},
    skip_stages=[2, 4],  # 跳过双引擎一致性（VBT 不可用）和 Walk-Forward（数据不足）
)
```

### 9.4 Stage 4 数据要求

Walk-Forward 按日历年切窗，数据跨度必须 `>= train_years + test_years` 才能生成 1 个窗口。默认 `train_years=2, test_years=1`，即至少需要 3 年数据。

## 11. A 股市场约束

### 11.1 必须遵守的过滤规则

所有 A 股策略必须遵守以下过滤规则（由 `build_ashare_risk_manager()` 默认启用）：

| 规则 | 说明 |
|------|------|
| ST 过滤 | 排除 ST / *ST / 退市股 |
| 新股过滤 | 排除上市不满 60 天的股票 |
| 涨跌停过滤 | 主板 10%、创业板/科创板 20%；涨停不买、跌停不卖 |
| 停牌过滤 | 停牌股不参与交易 |
| T+1 规则 | 当日买入次日才能卖出 |
| 重叠持仓保留 | 调仓时新旧持仓重叠部分保留，减少交易成本 |

### 11.2 有效板块前缀

A 股有效板块前缀（策略选股时应过滤）：

```python
_VALID_BOARD_PREFIXES = ("60", "00", "30", "68")
# 60: 沪市主板
# 00: 深市主板
# 30: 创业板
# 68: 科创板
```

### 11.3 股票代码格式

| 场景 | 格式 | 示例 |
|------|------|------|
| 内部标准 | `<代码>.<交易所>` | `600000.SH`、`000001.SZ` |
| 东财掘金 | `<交易所>.<代码>` | `SHSE.600000`、`SZSE.000001` |
| 纯数字 | `<代码>` | `600000` |

`SymbolConverter` 负责三种格式互转。策略层应使用内部标准格式（`600000.SH`）。

### 11.4 交易成本默认值

| 项目 | 默认值 | 说明 |
|------|--------|------|
| 佣金费率 | 0.00025（万 2.5） | `PercentageCommission` |
| 滑点比例 | 0.0001（万 1） | `PercentageSlippage` |
| 手数 | 100 股 | A 股 1 手 = 100 股 |
| 调仓容忍度 | 0.02（2%） | 小于此比例不调仓 |
| 初始资金 | 1,000,000 | 默认 100 万 |

## 14. 完整策略模板

新策略开发时，复制以下模板并替换 `<...>` 占位符：

```python
"""
<策略名>_v<版本号> - <策略中文名>（quantlab SignalStrategy 版）
====================================================================

原版 BaseStrategy (on_bar)：<策略路径>
- <原版逻辑简述>

v<版本号> 简化（遵循 quantlab/signals/base.py 契约）
------------------------------------------
- 策略层只输出"<选股条件>"（signal=1）或"不持有"（signal=0）
- <委托给 PortfolioConstructor 的逻辑>
- <委托给 RiskManager 的逻辑>

数据约定（DataAdapter 注入到 ctx.data[sym]）
-----------------------------------------
- open / high / low / close / volume
- pre_close / amount / market_cap
- <策略专用字段，如 pb / roe / industry_inflow_rank>
"""

from __future__ import annotations

import pandas as pd

from src.quantlab.signals.base import SignalStrategy


class <StrategyName>V<VersionNum>(SignalStrategy):
    """
    <策略中文名> V<版本号>（quantlab SignalStrategy）

    单标的信号规则（<选股维度>）：
        1. <规则1>
        2. <规则2>
        3. <规则3>

    TopN 截断由 PortfolioConstructor 决定，本类只输出"过没过"。

    signal ∈ {0, 1}：1=<满足条件想买>，0=不持有。
    """

    name = "<策略名>_v<版本号>"
    description = "<策略中文名> V<版本号> (quantlab) - <一句话说明>"

    def __init__(
        self,
        <param1>: int = 30,
        <param2>: float = 500.0,
    ):
        # 参数全部为基本类型，可 JSON 序列化
        self.<param1> = int(<param1>)
        self.<param2> = float(<param2>)

        # 入参合理性校验（启动即失败，不要在 .signal() 跑一半才崩）
        if self.<param1> < 1:
            raise ValueError(f"<param1> must be >= 1, got {<param1>}")
        if self.<param2> < 0:
            raise ValueError(f"<param2> must be >= 0, got {<param2>}")

    # ------------------------------------------------------------------ #
    # SignalStrategy 接口
    # ------------------------------------------------------------------ #
    def signal(
        self,
        ctx,
    ) -> pd.DataFrame:
        # 多标的遍历，严格保持 ctx.data.keys() 顺序
        out: dict[str, pd.Series] = {}
        for sym in ctx.data:
            out[sym] = self._signal_one(ctx, sym)

        # 完整 DataFrame(date × symbol)，整型（int8）节省内存
        df = pd.DataFrame(out).astype("int8")
        return df

    # ------------------------------------------------------------------ #
    # 单标逻辑（私有）
    # ------------------------------------------------------------------ #
    def _signal_one(
        self,
        ctx,
        sym: str,
    ) -> pd.Series:
        df = ctx.data[sym]

        # 数据不足时返回全 0
        if len(df) < <self.required_bars>:
            return pd.Series(0, index=df.index, dtype="int8")

        # ---- 1. <规则1> ----
        <rule1_ok> = ...

        # ---- 2. <规则2>（缺列降级为 True）----
        if "<col2>" in df.columns and df["<col2>"].notna().any():
            <rule2_ok> = (df["<col2>"] > self.<param2>).fillna(False)
        else:
            <rule2_ok> = pd.Series(True, index=df.index)

        # ---- 综合：全 AND ----
        qualified = (<rule1_ok> & <rule2_ok>)
        return qualified.astype("int8")


# ---------------------------------------------------------------------- #
# 工厂方法：方便 ExperimentRecord / CLI 用 kwargs 构造
# ---------------------------------------------------------------------- #
def make_<策略名>_v<版本号>(
    <param1>: int = 30,
    <param2>: float = 500.0,
) -> <StrategyName>V<VersionNum>:
    """显式工厂：避免某些调用方依赖默认参数顺序。"""
    return <StrategyName>V<VersionNum>(
        <param1>=<param1>,
        <param2>=<param2>,
    )


# ---------------------------------------------------------------------- #
# 典型参数网格（给 Optimizer / ParallelOptimizer 用）
# ---------------------------------------------------------------------- #
<STRATEGY_NAME>_PARAM_SPACE: dict = {
    "<param1>": [<value1>, <value2>, <value3>],
    "<param2>": [<value1>, <value2>, <value3>],
}
```
